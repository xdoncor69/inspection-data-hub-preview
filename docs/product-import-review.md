# Early product lookup and mandatory import-match review

Single Product debounces Item No. input for 300 ms, queries the complete official catalog using the existing safe catalog RPC and checks the full identifier exactly. It reports checking, already in catalog, no exact record or a query error as distinct states. Late responses are discarded when the input changes or clears. Check again is offered after errors. Review is disabled until the current Item check finishes and refreshes the catalog again before staging; known Items can be compared without filling all product fields first.

Batch comparison also refreshes the official catalog before classifying rows. Every catalog match (including identical records), repeated source row and invalid row blocks the new-product import button until individually resolved. The former bulk Skip existing and Skip all shortcuts are removed. Each matched record shows catalog versus source values; changed fields start unchecked. Apply selected fields updates that one Item through the existing administrator batch writer and removes the row only after confirmation. Keep existing / dismiss removes the review row without changing the catalog. Invalid/repeated rows can be discarded explicitly or corrected in the source and compared again.

Import new products accepts only selected rows classified as new, and only after all blockers are gone. It reuses the existing new-product writer, including duplicate and optimistic-concurrency protections. Source file replacement/clear invalidates older file reads and clears obsolete review state. Pending submissions stay explicitly unconfirmed and locked; clearing a review never cancels durable pending jobs.

The import flow no longer mutates the catalog array and schedules an indirect save. Both existing-item changes and new-item imports use the already deployed explicit writers. Existing source mappings, templates, parsing, identifier strings and backend permissions are preserved. Empty source fields retain existing catalog values. No database migration or business data cleanup was performed.

Code-only validation: 22 scripts compile. Tests cover exact live lookup/leading zeros, stale responses, failure versus not-found, early existing-item notice, manual review without retyping known data, per-field updates, identical matches, duplicate blockers, explicit dismissal, no bulk bypass, pending locks and administrator guards. Existing catalog writers, delivery exports and column-layout code were checked unchanged. No products or physical observations were created for testing; no browser, screenshots or rendered preview used.
